## Gecko in.touch 3: the community integration returns

Version 3.0.0 revives Dan Baker's original community repository using Gecko's official 2.1.1 integration as the foundation. It brings together reviewed community fixes and fork improvements, with substantially expanded Home Assistant lifecycle and service testing.

Thank you to the Gecko team for creating the official integration and client, and to everyone contributing fixes, reports and testing. Community contributions and additional maintainers are welcome.

### Highlights

- Reconnection cleanup, current-client zone rebinding, sparse-state handling and reliable entity lifecycle/unload behavior.
- Pump controls based on reported speed configuration, low-first startup for supported two-speed pumps, and separate manual/heating/filtration/flow-check telemetry.
- RGB, brightness and effect controls on lighting zones that report support; on/off controls for simpler lights.
- Watercare presets, eco/heat-pump status, current/target temperature mirrors and connection/RF/device telemetry.
- Read-only Waterlab cloud readings, including pH/ORP and additional measurements when supplied by the account. Some cloud readings come from manual tests or computed values, not live Waterlab hardware.
- Identity-free shareable diagnostics, clearer translated command errors, Home Assistant-managed application credentials and translated entity names/icons.
- One installation: the client is bundled inside `custom_components/gecko`.

### Upgrading from Gecko's official integration

This integration uses the same `gecko` domain and replaces the official files in place. A higher version number does not automatically switch HACS repositories.

1. Take a Home Assistant backup.
2. Uninstall the official Gecko download **in HACS**. Keep the configured Gecko integration under **Settings → Devices & services**: do not delete its config entry.
3. Add `https://github.com/dansbaker/gecko-intouch3-home-assistant` as a HACS custom repository, category **Integration**, then download **3.0.0**.
4. Restart Home Assistant after installing the replacement. Existing official config-entry data, entity IDs and user customizations are retained where applicable. Do not leave two HACS repositories managing the same directory.

For a manual installation, extract `gecko.zip` into `/config/custom_components/gecko/` so that `manifest.json` and the `gecko_iot_client` directory are directly inside that folder. Restart HA afterward.

Users of the original `gecko_spa` integration (v0.1.x) need to configure Gecko again and update references to the old entities; those identities are different from the official integration. Keep a backup before that migration.

### Validation and limits

- 594 tests and 46 subtests passed against Home Assistant 2026.9.4 and 2026.10.4.
- Config flow, all control platforms, shared entity handling and diagnostics have full statement/branch coverage; both sensor platforms exceed 95% combined coverage.
- Development snapshots were deployed successfully on a real HA 2026.10.4 installation, preserving the nine existing spa entity IDs and receiving fresh reports. Version 3.0.0 is the first public release of this revival.
- Available features depend on the spa and the data Gecko exposes. Color control, additional-pump configurations and Waterlab chemistry require testing on equipment that supplies those capabilities. Automated tests are not a substitute for that hardware confirmation.
- Target-temperature mirrors no longer generate measurement statistics. Untyped MQTT ORP extensions retain their values without guessing a voltage unit; explicit-unit Waterlab readings retain their physical units.
- This is an independently maintained custom integration, not an integration accepted into Home Assistant Core.
