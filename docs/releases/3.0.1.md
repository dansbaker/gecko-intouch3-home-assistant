## Gecko in.touch 3 — compatibility and community diagnostics

Version 3.0.1 improves Home Assistant compatibility, corrects misleading device metadata and makes it easier to report hardware the maintainers do not own.

### Community fixes and acknowledgements

Thank you **@cwm12345** for testing on two spas and contributing:

- [PR #10](https://github.com/dansbaker/gecko-intouch3-home-assistant/pull/10): migration instructions for Home Assistant 2026.11's built-in Marketplace, preserving existing Gecko configuration and entities.
- [PR #11](https://github.com/dansbaker/gecko-intouch3-home-assistant/pull/11): valid suggested binary-sensor entity IDs for spa names containing trailing spaces or punctuation, and support for the native climate temperature API introduced in HA 2026.11.
- [Issue #12](https://github.com/dansbaker/gecko-intouch3-home-assistant/issues/12): investigation of unavailable firmware data and incorrect CO serial numbers. This report exposed an unsupported assumption in our code; CO serials now come only from explicit serial fields, never from `vesselId` or a copied EN serial.

Additional maintainer tests cover both climate API paths, metadata availability/recovery and preservation of existing entity identities across reloads. Firmware and serial sensors are unavailable when their values are missing. Genuine supplied metadata remains supported, and sparse updates retain the last supplied values. This release does not unlock the identity shadow when Gecko denies third-party access; it does not invent missing firmware versions.

### Easier hardware reports

- A dedicated hardware compatibility issue form and a [step-by-step capture guide](https://github.com/dansbaker/gecko-intouch3-home-assistant/blob/master/docs/HARDWARE_REPORTING.md) explain how to download before/after diagnostics while operating one supported control in the Gecko app. No terminal or packet capture is required for an initial report.
- Diagnostics include HA/integration versions, capture time, anonymous zone labels, numeric RGB state and allowlisted Waterlab metadata. Files are downloaded and attached manually; nothing is uploaded automatically.
- Waterlab attributes distinguish measurement timestamps/age from successful polling. Unknown timestamps and future clock skew are identified; no arbitrary sample expiry is assumed.
- Compatibility documentation distinguishes owner-tested equipment from automated fixtures. Initial replay fixtures are explicitly synthetic, not hardware recordings.

### Maintenance and validation

- Scheduled HA compatibility checks, dependency update proposals, Python correctness linting and broader integration coverage regression guards.
- A rule-by-rule Core adoption evidence checklist, release testing checklist and rollback instructions. These do not claim a Home Assistant quality tier.
- 631 tests pass in the pinned HA 2026.9.4 environment, along with config-flow, entity and integration coverage gates, lint and standalone client checks. Both climate API paths have regression tests; a direct check also passed against the real HA 2026.11 native temperature API. A full HA 2026.11 suite was not established because the available test harness is incompatible with that release.
- No live spa commands were performed for this release. Waterlab, RGB/effects and other hardware-specific behaviour still benefit from owner testing.

### Upgrade

Back up Home Assistant, update this repository to **3.0.1** through HACS/Marketplace and restart HA. Existing Gecko entity identities are retained. If moving from the official repository, follow the version-specific migration instructions in the README; do not delete the configured Gecko integration. Missing firmware or CO serial values may now appear unavailable rather than showing unknown or a misidentified vessel ID.
